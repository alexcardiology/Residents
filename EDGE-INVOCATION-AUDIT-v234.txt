WHAT THIS REPLACEMENT CHANGES
-----------------------------
1. Adds assets/edge-invocation-optimizer-v234.js.
2. Loads it before app.js and before the public El Médico UI.
3. Canonicalizes old authenticated duty aliases to the already-used
   duty-bot-v17 endpoint.
4. De-duplicates identical concurrent read-only Edge requests.
5. Caches successful identical El Médico schedule queries for 5 minutes.
6. Caches duty-contact lookups for 30 minutes.
7. Uses sessionStorage only, so caches disappear when the browser session ends.
8. Does NOT cache or suppress:
   - admin-users
   - push-notify
   - AI curriculum generation
   - account writes
   - attendance writes
   - any other privileged/write function

USER-FACING EFFECT
------------------
Normal use should look the same.

Examples:
- Asking the same El Médico question twice within 5 minutes:
  first request = server call
  repeated request = instant cached answer

- Double-click / duplicate event handler:
  only one identical request is allowed in flight.

- Old compatibility code trying duty-bot-fast/smart:
  it is routed to the current duty-bot-v17 endpoint instead of creating a
  multi-function fallback chain.

WHAT THIS CANNOT FIX BY ITSELF
------------------------------
If the 592k invocations are being caused by direct external traffic against a
public Edge endpoint, browser-side caching cannot stop those callers.

The strongest next step in that case is to inspect Supabase Edge Function logs
by function name and then either:
- protect/retire unused public endpoints, or
- replace the public schedule bot with a database-backed/static schedule query
  that does not require an Edge invocation per question.
