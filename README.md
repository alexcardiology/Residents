# Resident Training v1.0.61 — Approval / Review Action Hotfix

This update fixes the `column "is_read" does not exist` error introduced by the v1.0.52 automatic-read triggers.

## What changed

- Logbook Approve/Reject actions now complete normally.
- The related approval-request message is automatically marked read using the real `private_messages.read_at` column.
- The resident still receives the normal approval/rejection update generated by the logbook workflow.
- Review reconsideration Accept/Keep-original actions no longer fail on the same read-state bug.
- Quick logbook approval no longer asks for a browser confirmation; clicking Approve acts immediately.
- Review modification/save submits directly; there is no extra confirmation prompt.
- Owner Inbox review notifications show the actual review content, resident, domain/category, sentiment, date, place and reviewer.
- When a review is changed after reconsideration, the notification is explicitly `Review modified after reconsideration 💡`, not “submitted”.
- Original review text is preserved in new database fields before a reconsideration modification.

## Install

1. Run `sql/resident_training_v1.0.61.sql` in Supabase SQL Editor.
2. Replace `app.html`, `index.html`, `assets/app.js`, and `assets/style.css`.
3. Hard refresh the site.

No curriculum, assessment, logbook, review, or account records are deleted by this migration.
